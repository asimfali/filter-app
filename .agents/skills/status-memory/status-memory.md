# status-memory: канонический протокол

Перенесён из набора agent-kit. Единственный источник правил памяти планов.

Единственный источник правил для памяти планов. Рантайм-обёртки (OpenCode,
Claude Code, Codex) не копируют этот текст, а отправляют читать его.

## 1. Назначение

Единая точка доступа агента к `status/` проекта: карта планов, прогресс,
«на чём остановились», итоги выполненного. Планы целиком в контекст не читаются.

## 2. Состав

- `scripts/status_summary.py` — скрипт (stdlib, без зависимостей).
- `status/` — планы в markdown, `status/summary.md` — кэш, пишет только скрипт.
- Этот файл — протокол. Лежит рядом с SKILL.md в `.agents/skills/status-memory/`.

## 3. Запуск

```
python scripts/status_summary.py <режим> [план] [--dir status] [--date=auto|mtime|git]
```

- Вывод — markdown в stdout, готов к вставке в контекст (ориентир: ≤50 строк).
- Ошибки и warning'и — в stderr.
- Дата по умолчанию `auto`: `git log -1 --format=%cs -- <файл>` в репозитории,
  иначе mtime.

## 4. Источник истины и кэш

- Истина — чекбоксы `[ ]`/`[x]` в планах.
- `status/summary.md` пересобирается скриптом при каждом вызове в любом режиме.
  Никто, кроме скрипта, его не пишет; рассинхрон невозможен.

## 5. Критерий «это план»

Файл `status/*.md` — план, если первый заголовок начинается с `# План:` **или**
в нём есть ≥1 валидный чекбокс. Остальное игнорируется; `overview` подсказывает
убрать не-планы из папки.

## 6. Формат плана

1. Этап — заголовок `##` (или `###` внутри части); пункты — чекбоксы.
2. Текст закрытого пункта самодостаточен: что и как сделано.
3. Вложенность чекбоксов — не глубже 1 уровня.
4. Чекбоксы вне таблиц, цитат и код-блоков; нарушение — warning `файл:строка`.
5. Этап закрыт ⇔ закрыты все его чекбоксы.

## 7. Режимы

| Режим | Аргумент | Отдаёт |
|---|---|---|
| `overview` | — | по каждому плану: имя, прогресс, следующий незакрытый пункт, дата изменения |
| `next` | план | последний начатый этап и его незакрытые пункты |
| `plan` | план | незакрытые пункты по этапам + заголовки закрытых этапов |
| `done` | план | тексты выполненных пунктов по этапам |
| `full` | план | план целиком (escape hatch) |

«Последний начатый этап» — самый нижний этап, в котором уже закрыт хотя бы
один пункт; если он закрыт целиком — следующий за ним этап с открытыми
пунктами; если начатых нет — первый этап с открытыми пунктами.
Все пункты плана закрыты → «план завершён»; в архив переносит агент или
человек, скрипт файлы не перемещает.

## 8. Формат summary.md

```
# Сводка планов (обновлено YYYY-MM-DD HH:MM)

| План | Прогресс | Следующий этап | Изменён |
|---|---|---|---|
| DEALERS_CHECK | 8/12 (66%) | Часть 2: вебхук на сайте | 2026-11-19 |
```

Для человека и истории прогресса в git-диффах. Агенту читать не нужно.

## 9. Обёртки под рантаймы

- **OpenCode:** скилл `status-memory` (этот каталог).
- **Claude Code:** каталог `.claude/skills` он не увидит (наши скиллы в `.agents/skills`), поэтому работает строка в `AGENTS.md` проекта — как у Codex.
- **Codex, DSH, opencode:** скилл из `.agents/skills` либо строка в `AGENTS.md` проекта.

Обёртка не копирует протокол, а ссылается на этот файл.

## 10. Правила переезда проекта

1. Инструкции проекта — один файл `AGENTS.md` в корне. Других имён нет.
2. `CLAUDE.md` не создаётся: Claude Code читает `AGENTS.md`, если `CLAUDE.md`
   рядом отсутствует. Симлинки не нужны и на Windows не работают.
3. Если в проекте уже есть `CLAUDE.md` — переименовать его в `AGENTS.md`
   (`git mv CLAUDE.md AGENTS.md`); если есть оба файла — слить содержимое в
   `AGENTS.md` осмысленно, не механически, и удалить `CLAUDE.md`.
4. Codex и OpenCode читают `AGENTS.md` напрямую.
5. Ссылки на `CLAUDE.md` в документации проекта, скриптах и `install.sh`
   переписать на `AGENTS.md` — по `grep -rn 'CLAUDE'`, чтобы не осталось
   указаний на несуществующий файл.

## 11. Не входит

Письмо в планы (кроме кэша), перемещение в архив, кросс-проектные ссылки,
интеграция с `ab`.
