# status-memory

Долговременные планы проекта живут в `status/` как markdown с чекбоксами
`[ ]`/`[x]`. В контекст их целиком не читают: всё достаётся через скрипт.

## Вызов

Из корня проекта:

```
python scripts/status_summary.py <режим> [план]
```

| Режим | Зачем |
|---|---|
| `overview` | старт: все планы, прогресс, следующий незакрытый этап |
| `next <план>` | на чём остановились: последний начатый этап и его открытые пункты |
| `plan <план>` | открытые пункты по этапам, закрытые — только заголовками |
| `done <план>` | как сделано ранее: тексты выполненных пунктов |

## Протокол

1. Старт задачи или новая сессия — `overview`. Планы до выбора режима не читать.
2. Работа по плану — `next`. Закрыл пункт — поставь `[x]` в файле; кэш
   `status/summary.md` скрипт пересоберёт сам при следующем вызове.
3. Нужно понять, как сделано раньше — `done`, не `full`.
4. Не вызывать `ls status/`, не читать `summary.md` и планы целиком. `full` —
   только когда без него никак.
5. Warning в stderr («нестандартная строка») — поправь разметку плана и повтори.
6. `docs/DECISIONS.md` — принятые решения и «почему» (append-only); `status/` —
   долгие планы и «что дальше». Не дублировать.

## Формат плана

- Первый заголовок — `# План: <тема>`.
- Этап — заголовок `##` (или `###` внутри части), пункты — чекбоксы.
- Закрытый пункт самодостаточен: что и как сделано. Режим `done` отдаёт только
  текст пунктов, поэтому «[x] сделал» бесполезен.
- Вложенность чекбоксов — не глубже 1 уровня, вне таблиц и код-блоков.

Полная спецификация (режимы, критерии плана, summary, правила переезда) —
`.agents/skills/status-memory/status-memory.md`. Читать при настройке или
спорном случае.
