# Решения и договорённости

Общая память проекта для агентов (opencode и Claude Code) и людей. Сюда попадает только то, что не
выводится из кода и пригодится в будущих сессиях: принятые решения, договорённости, причины отказа
от вариантов, особенности окружения.

## Формат записи

Дописывай **в конец** файла — писать могут два агента параллельно (opencode и Claude Code), поэтому
файл append-only: существующие записи не редактируй и не удаляй.

    ## YYYY-MM-DD — краткая тема

    - Контекст: почему возник вопрос.
    - Решение: что решили.
    - Следствия: что теперь важно помнить, что сломается при ином решении.

Не записывай секреты, пароли, токены и то, что уже есть в `CLAUDE.md` / `.claude/CLAUDE.md`. Быстро
добавить запись — команда `/remember <суть>`.

## 2026-11-11 — Память проекта, общая для opencode и Claude Code

- Контекст: нужна «память на диске» между сессиями и инструментами; `AGENTS.md` добавлять нельзя —
  в opencode он затеняет `CLAUDE.md`, и Claude Code перестанет видеть общие правила.
- Решение: append-only журнал `docs/DECISIONS.md` + правило в `CLAUDE.md` + команда `/remember`.
- Следствия: важные решения фиксируем только здесь; `AGENTS.md` не создавать, пока оба инструмента
  не читают один и тот же файл инструкций.

## 2026-11-18 — Экран «Дилеры»: каркас до контракта портала

- Контекст: портал делает справочник дилеров (`/api/v1/dealers/`), filter-app — интерфейс заполнения
  (DEALERS_CHECK_PLAN.md, часть 3). Контракт и точные RBAC-коды придут письмом позже.
- Решение: экран собран на предположениях, но все места, зависящие от контракта, собраны в
  `src/api/dealers.js` (путь, query-параметры, ключ записи, способ отмены авторизации) и в
  `src/utils/permissions.js` (`dealers.view` / `dealers.write` / `portal.page.dealers` — предварительные).
  Отмена авторизации — `PATCH {is_active: false}`, ключ записи — ИНН; код `D#####` только на чтение.
- Следствия: когда придёт контракт, править `src/api/dealers.js` и коды прав, страницу/модалку —
  только если поменяется набор полей. Ответственность за код дилера — на портале; во фронте его
  нельзя редактировать и при создании он пустой («присвоит портал»).

## 2026-11-18 — Дилеры: сверка с реальным контрактом портала (правка предыдущей записи)

- Контекст: портал уже отдал `apps.dealers`, предварительные предположения не совпали.
- Решение: путь — `/api/v1/dealers/dealers/` (include + префикс роутера); список приходит
  массивом без конверта (нет пагинации), create/update/revoke/restore — конвертом `{success, data}`;
  ключ записи — `id`, не ИНН (ИНН редактируемый); отмена авторизации — `POST <id>/revoke/`,
  восстановление — `POST <id>/restore/` (поле `reason` уходит в `note`); право одно —
  `portal.dealers.write`, бэкенд требует его и на чтение.
- Следствия: фронт фильтрует и страницует список на клиенте, пока портал не включит
  `filter_backends`/пагинацию; `?search/?is_active` уже отправляются и начнут работать без правок.
  Когда ответ станет `{count, results}`, клиентская ветка отключится сама (проверка на массив).

## 2026-11-18 — Дилеры: путь без двойного сегмента и импорт из xlsx

- Контекст: портал `dev@6a12ecf` убрал префикс роутера (`router.register(r'')`), поэтому API
  переехал с `/api/v1/dealers/dealers/` на `/api/v1/dealers/`. Одним коммитом добавлен импорт
  справочника из xlsx (аналог PDF/DXF-кнопок).
- Решение: `BASE` в `src/api/dealers.js` — `/api/v1/dealers`; старый двойной путь больше не
  поддерживается (портал поменял его сразу и без промежуточного периода).
  Импорт: `POST /dealers/import/` (multipart `file=.xlsx`) → `{data: {task_id}}`, затем опрос
  `GET /dealers/{taskId}/import-status/` (в пути — id **задачи**, не дилера) каждые 2 с до
  `COMPLETED`/`FAILED`; поля `rows_total/created/updated/revoked/errors[{row, inn, error}]/result`.
  UI — кнопка «Импорт из xlsx» на экране дилеров (`DealerImportModal`), итог со счётчиками и
  таблицей битых строк, окно можно закрыть — задача продолжается на портале.
- Следствия: импорт требует работающего celery-воркера портала, иначе задача навсегда останется
  в `PENDING` (опрос крутится, пока окно открыто). Битая строка не валит импорт — она в `errors`,
  применённые строки остаются. Статистика перезагружается листом дилеров после завершения.
