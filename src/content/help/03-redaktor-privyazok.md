# Редактор привязок: привязка товаров к осям и настройка графа

**Редактор привязок** — режим внутри [конфигуратора](help:02-konfigurator)
для администраторов каталога. В отличие от обычного «Фильтр графа», здесь
граф используется не для поиска изделий, а для того, чтобы задавать саму
классификацию: привязывать товары к значениям осей и настраивать, какие
сочетания значений вообще допустимы в графе.

## 1. Доступ

Переключатель **«Редактор привязок 🔧»** виден, если у вас есть право
на просмотр привязок. Без права на **изменение** привязок (`catalog.binding.write`)
режим открывается только для чтения — перетаскивание и клики по графу не
дают эффекта, об этом явно предупреждает жёлтая плашка вверху.

## 2. Найдите товары, которые нужно привязать

Есть два независимых способа:

- **Фильтр товаров по тегам** (панель вверху, как в обычном конфигураторе,
  но по всем осям, а не только по первым) — сужает список слева от графа
  до товаров, подходящих под выбранные значения. Список делится на
  **«В цепочке»** (полностью попадающие под фильтр) и **«Неполные»**
  (у товара часть нужных осей просто не заполнена — под каждым указано,
  каких именно осей не хватает).
- **Поиск по названию** (панель справа от графа) — свободный текстовый
  поиск по всем товарам выбранного типа продукции, не зависит от тегов.
  Есть переключатели **«Regex»** (искать по регулярному выражению) и
  **«∅ Без осей»** (показать только товары, у которых вообще нет ни одной
  привязки — удобно для первичной классификации новых товаров).

В обеих панелях можно выделить сразу несколько товаров (клик — один,
Shift+клик — диапазон, Ctrl+клик — добавить к выделению).

## 3. Подрежим «Привязать товар»

1. Кликните по одному или нескольким узлам графа, чтобы задать, к каким
   значениям осей привязать товар — так же, как выбор узлов в обычном
   конфигураторе (клик — заменить на этой оси, Ctrl+клик — добавить ещё
   одну ось к цепочке).
2. Перетащите товар (или несколько выделенных) из любой панели слева/справа
   на нужный узел графа.

- Если перед перетаскиванием вы не выделяли цепочку из нескольких узлов —
  товар привязывается к одному значению одной оси.
- Если выделили цепочку сразу по нескольким осям — перетаскивание на любой
  узел этой цепочки привязывает товар **сразу ко всем выбранным осям**
  за один раз.
- Перетаскивание товара из списка **«Неполные»** — особый случай: узлы
  графа подсвечиваются как зона для перетаскивания только у тех осей,
  которых товару не хватает (остальные не трогаются). Так удобно
  доклассифицировать товар, у которого не хватает 1-2 значений, не рискуя
  случайно изменить уже заполненные оси.
- Если у товара **уже есть** значение на этой оси — перетаскивание на другой
  узел той же оси просто заменяет старое значение новым (переклассификация),
  без ошибок и дублей. Не бойтесь перепривязывать товар другим значением,
  если ошиблись.

**«−ось»** (рядом со списком «В цепочке») — отвязывает выбранную ось сразу
у всех товаров текущей цепочки. Полезно для массовой чистки, когда нужно
снять устаревшую привязку у большой группы товаров разом.

## 4. Подрежим «Связать узлы»

Здесь вы не привязываете товары, а настраиваете сам граф — какие сочетания
значений соседних осей вообще считаются допустимыми (это и есть рёбра,
которые видит любой пользователь конфигуратора).

- Перетащите от одного узла к другому — создаёт связь между ними.
- Кликните по существующему ребру — удаляет связь.
- Shift+клик по нескольким узлам после выбора узла-источника — накопить
  несколько целей и связать источник со всеми разом одним действием.

Связать можно только значения **соседних по порядку осей** — через ось
напрямую соединить нельзя, будет ошибка. Это изменение не личное и не
про конкретный товар — оно меняет граф для всех, кто откроет конфигуратор
после вас, так что стоит быть аккуратнее, особенно с удалением связей.

## 5. Очистка «осиротевших» привязок

Если кликнуть по одиночному узлу **справочной** оси (паспорт, условие —
не основной классификатор изделия), не выбирая перед этим ничего на
классифицирующих осях, редактор переключается в режим поиска
«осиротевших» привязок: товаров, у которых это справочное значение
физически привязано, но родительское классифицирующее значение, к
которому оно должно относиться по правилам, у товара либо не заполнено,
либо не совпадает.

Это не просто мусор в данных — такая привязка может привести к тому, что
товар неверно попадёт в выдачу поиска по этому справочному значению или
подтянет не тот документ/паспорт. Список найденных «сирот» показывается
под графом; чтобы почистить — выделите их и снимите привязку через «−ось»,
как описано выше.
